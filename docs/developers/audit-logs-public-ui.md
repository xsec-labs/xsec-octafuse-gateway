# 审计日志公共 UI

`/gateway/audit-logs` 使用 `@xsec/ui-react` 的页头、字段、复选框、按钮、表格、状态反馈与 Dialog。常用事件、操作人、邮箱和关联编号直接显示；来源和原因收进“更多筛选”，已指定这些条件的深链自动展开。预算前后值、用户跳转、metadata 差异、原因与来源、关联编号及原始审计记录保持可读。

筛选在客户端 URL 初始化后发出一次列表读取。重复参数与逗号分隔值按已有业务枚举去重；事件、操作人、来源和原因保留至少一个已选项，全选操作人、来源和原因时省略对应参数。显式空日期表示全部时间，业务时区字段应用后提交 UTC 范围。无效起止顺序在两个字段显示错误，保持已应用范围。

列表、原因目录和币种各有读取所有者，复用 shell 请求边界的取消与完整响应正文 20 秒预算。原因目录确认后读取列表；失败显示对应错误和手动重读。读取中或失败时暂停旧行和总数，币种确认前暂停金额。列表成功响应校验分页、身份、时间、文本及有限金额。审计 JSON 解析失败显示错误，详情仍提供原始记录。复制通过真实 Clipboard；公共 Dialog 处理焦点、Escape 与返回原按钮。

高级筛选在展开时挂载，选择状态由页面保有；每次成功读取计算差异，详情消费同一差异结果。新增依赖为零，包清单与锁文件保持。四种语言各新增七项提示并更新页面说明。

## 日期仓储修复

PostgreSQL 的 TIMESTAMPTZ 比较原先按连接时区解释无偏移的 SQL 日期文本，与 API 的 UTC 约定不同。基线在上海连接时区下，SQL 范围查不到应有的 61 条记录；显式 ISO 范围正常。全局审计起止绑定现在为该 SQL 格式标明 UTC，保留 ISO 和显式偏移。

该独立修复已本地集成到主分支 `a8845bf20187988748d04b94f0b7bf99ce407e1e`。真实 PostgreSQL 回归覆盖 UTC、上海、洛杉矶三个连接时区，SQL、ISO、显式偏移、毫秒、包含边界及开放起止范围；主仓源码再次通过同一真实数据库测试。
